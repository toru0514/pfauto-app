# Playwright セレクタ改善計画 — Playwright CLI (codegen) 活用

## Context

Handmade Sync Hub は、Creema・minne・BASE・iichi の4つの日本ECプラットフォームに対して、Google Sheets の商品データを元に Playwright でフォーム入力を自動化し下書き保存するアプリ。

**現在の問題:**
- セレクタはブラウザの検証（DevTools）からコピーして作成 → CSSクラス名ベースで壊れやすい
- 一部の必須入力フィールドが未実装（TODOコメントあり）
- CSSモジュールのハッシュ値（`--MsSNs`, `--y8Xy7`等）を含むセレクタはビルドのたびに変わる

**目標:** `npx playwright codegen` を使い、より堅牢なセレクタ（role/label/text ベース）に置き換え、不足フィールドを追加する。

## Phase 1: Codegen セッション（ユーザーがローカルで実施）⬜ 次のステップ

> **この Phase はユーザー自身がローカルマシンで実行する必要があります。**
> 各プラットフォームにログイン済みの状態でブラウザ操作を記録します。

### 実行順序（認証の簡単な順）

#### 1. Creema（email + password）
```bash
# ログインフロー記録 + auth保存
npx playwright codegen --save-storage=playwright/.auth/creema-auth.json https://www.creema.jp/user/login

# フォーム記録（auth読み込み）
npx playwright codegen --load-storage=playwright/.auth/creema-auth.json https://www.creema.jp/my/item/create
```

#### 2. iichi（email + password）
```bash
npx playwright codegen --save-storage=playwright/.auth/iichi-auth.json https://www.iichi.com/signin
npx playwright codegen --load-storage=playwright/.auth/iichi-auth.json https://www.iichi.com/your/item/create
```

#### 3. BASE（email + password + 2FA）
```bash
# 2FA があるため、ログイン後に auth を保存
npx playwright codegen --save-storage=playwright/.auth/base-auth.json https://admin.thebase.com/users/login
npx playwright codegen --load-storage=playwright/.auth/base-auth.json https://admin.thebase.com/shop_admin/items/add
```

#### 4. minne（magic link）
```bash
# magic link でのログイン後に auth を保存
npx playwright codegen --save-storage=playwright/.auth/minne-auth.json https://minne.com/signin
npx playwright codegen --load-storage=playwright/.auth/minne-auth.json https://minne.com/account/products/new
```

### Codegen 中にユーザーがやること
- **全てのフォームフィールド**を操作する（タイトル、説明、カテゴリ、価格、在庫、画像、配送関連等）
- 現在自動化されていないフィールドも含めて操作し、セレクタを収集
- 生成されたコードを `playwright/tests/codegen-output/` に保存:
  - `creema-login.ts`, `creema-form.ts`
  - `minne-login.ts`, `minne-form.ts`
  - `base-login.ts`, `base-form.ts`
  - `iichi-login.ts`, `iichi-form.ts`

## Phase 2: Codegen セレクタの統合（開発者が実施）

### セレクタ優先順位（上ほど堅牢）
1. **Role ベース:** `getByRole("button", { name: "ログイン" })`
2. **Label ベース:** `getByLabel("メールアドレス")`
3. **Placeholder ベース:** `getByPlaceholder("商品名")`
4. **Text ベース:** `getByText("保存")`
5. **CSS name属性:** `input[name='email']`
6. **CSS id:** `#form-item-title`
7. **XPath:** 最終手段のみ

### プラットフォーム別の主な置き換え対象

## Phase 3: Spec ファイルのリファクタリング（開発者が実施）

各specファイルを Page Object を使う形にリファクタリング:

```typescript
// Before: 直接セレクタ操作
await page.fill(selectors.titleInput, mapped.title);
await page.fill(selectors.priceInput, String(mapped.price));

// After: Page Object 経由
const creemaPage = new CreemaPage(page);
await creemaPage.fillProductForm(mapped);
```

Page Object が encapsulate するもの:
- セレクタ定義（Locator）
- ログインフロー
- フォーム入力ロジック
- カテゴリ選択（依存関係のあるドロップダウン）
- 画像アップロード
- 下書き保存
